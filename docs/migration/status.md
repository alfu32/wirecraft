# Current migration status

Wirecraft **0.6.0** restores the compiler/template sets and retains the reported canvas, routing, export and editor corrections. **The complete migration remains unfinished.** The authoritative source baseline is Threadworks 2.6.7 at `7d392d3a0e30b86445e00e7c03032a5188b26593`. The source checkout, its running application, live Wirecraft project/settings, and untracked root `example.orch` / `example.copy.orch` were preserved. Changes use Conventional Commits; only patch/minor versions are authorized.

## Compiler/template milestone

The six original template sets (C, Go, Kotlin, Node.js, PHP, QuickJS; 90 hashed resources) are embedded. Shared `compile.project`, `compiler.templates`, `compiler.export` services are connected to desktop Generate, CLI and MCP workbench. Inspector technology choices and canonical filesystem layout IDs are restored. Portable compiler bundles replace generated JVM compiler classes; model role overrides, project files and literal static companions are supported outside the still-pending C template path.

Real Go/Node/Kotlin/PHP/QuickJS producer → typed FIFO → consumer → shutdown fixtures execute successfully. Node/PHP single and filesystem layouts and Kotlin single/source-set layouts are covered. CLI custom-template export/reuse and real HTTP MCP catalog/generation/export pass. Rendering rejects malformed templates, bounds instructions/output, and generation rejects unsafe/duplicate paths and unresolved scope connections. C bundle execution/unsupported overrides, generic composite boundary channels and mixed-language delegation return explicit errors. See [compiler-templates.md](compiler-templates.md) for the exact retained contract and examples. Language generation does not imply broader inline LSP/coloring parity.

0.6.0 checks: **81 Rust tests passed, zero failed or ignored**, with the optional real toolchains explicitly enabled; formatting, workspace build and strict Clippy passed. The default test invocation leaves two optional toolchain tests ignored unless requested. All 90 assets match the exact baseline git objects. CLI/API/MCP compiler workflows pass. Native Generate produced and executed the Node.js example once; the full new native suite did not pass because Wayland/isolated GTK picker observation was inconsistent, so native compiler-export picker completion remains unverified. The previous 0.5.0 native suites below are historical, not a claim about this new picker flow. Details: [verification](evidence/v0.6.0/verification.json).

## Remaining migration and exact continuation

Main gaps: C source capabilities and C template overrides; remaining parameterized collection constructors; full Go/Kotlin/JavaScript/PHP/QuickJS parity including template composite boundary channels, capability variants and aggregate mixed-language delegation; broader-language inline navigation/completion and multicursor; OAuth identity; editable canvas paper overlays; exact legacy typography/Markdown print fidelity. The JVM plugin ABI is deliberately incompatible, while stored plugin data survives. Network AI/browser authorization were unavailable stubs in the baseline; clipboard assistance works. Already-issued hover/completion requests may finish after dismissal, with stale results rejected; generic LSP request cancellation is available. Extremely crowded/overlapping layouts can exceed the bounded routing search and receive an explicit finding rather than a hidden or box-piercing route.

Next functional slice: **C source capabilities**, using `../threadworks/compilers-impl/src/main/resources/compiler-templates/c/link-declaration.peb`, `CCompiler.generatedFunctionHeader`, and its source-capability test fixture. Implement typed supplier-source materialization and parameter substitution in core generation; expose only incoming suppliers to a consumer; preserve origin maps; compile/run an isolated fixture with external clang and verify completion/hover/diagnostics. The initial portable template/bundle and five-language slice is now connected; next expand its boundary channels, capabilities, collection types and mixed-language dispatch. Keep these requirements open in parity.md; Neither release claims full migration completion.
