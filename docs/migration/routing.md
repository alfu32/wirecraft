# Routing correction: native diagonals

Reference: Threadworks 2.6.7 at `7d392d3a0e30b86445e00e7c03032a5188b26593`, `app-desktop/src/main/kotlin/com/threadwork/app/ui/ThreadworkDesktopApp.kt`, `bestRouteBetween`, `routeCandidates`, `chamferOrthogonalTurns`, `routeCost` (6434–6547 in that revision).

The previous Wirecraft router searched horizontal/vertical lanes and added diagonal corner cuts afterwards. That was an approximation and biased the drawing toward H/V runs. It did not migrate the original route-selection behavior. The correction evaluates long 45° runs before choosing and reserving a route; the goal is shortest readable paths, not a fixed percentage of diagonal segments.

## Algorithm and retained differences

1. Migrate the JVM candidate family: direct snapped route, horizontal/vertical lane candidates around the midpoint in 40-unit steps (span seven), and both long-diagonal alternatives. Orthogonal candidate turns use the reference 22-unit maximum chamfer **before scoring**.
2. Score Euclidean length, 18 units per intermediate bend and 2500 per crossing. Nine golden cases are generated by compiling and executing the actual extracted Kotlin methods, not a handwritten second implementation. They cover straight routes, both diagonal placements, all quadrants, a blocking rectangle and an occupied crossing.
3. Keep Wirecraft's hard constraints: reject box penetration and coincident channel runs. Near parallel lanes retain a 50-unit spacing penalty within ten world units. The source instead uses a 75000 soft obstacle penalty and can ultimately return a line through a box; that unsafe fallback is deliberately not restored. Existing port geometry, padding, angular order, provider boxes and dependency flagpoles are retained. Thus this is source candidate/scoring parity for the recorded cases, not a claim that every crowded drawing is pixel-identical.
4. If reference candidates cannot fit, use bounded A* visibility search with horizontal, vertical and both diagonal axes. Endpoint projections add exact 45° connections on the nonuniform grid, including fractional ports. Costs use Euclidean distance, the same bend/crossing weights and an admissible Euclidean heuristic. The 250000-vertex limit remains. An impossible route is reported rather than drawn through a box.
5. Reserve the final diagonal segments for later links. Remove the global post-routing corner-cut pass, which previously changed geometry after reservations. Simplify collinear segments in every direction; crossing bridges and vector export consume the same final geometry.

World coordinates remain f64. Lane midpoints and chamfers retain fractions instead of rounding like `java.awt.Point`; this preserves translation and fractional composite ports. Golden cases use integer coordinates where the outputs coincide exactly.
